# テスト写真の分析と設計への反映

作成日: 2026-11-11
対象: `testdata/setA` 〜 `setC`（3人 × 4枚 = 12枚）

> ⚠️ `testdata/` は `.gitignore` で除外しています。GitHub は公開リポジトリになるので、写真は絶対に含めません。

## 1. 写真の一覧

| セット | 選択順（受領順） | 向き |
|---|---|---|
| A | 正面 → 斜め → 横顔 → あおり | 斜め・横顔とも右向き |
| B | 正面 → 斜め → あおり → 横顔 | 斜め・横顔とも右向き |
| C | 横顔 → あおり → 正面 → 斜め | **斜め・横顔とも左向き** |

- サイズはすべて 2576 × 1717 px（3:2 横長）
  - チャットで受け取る際に縮小されている可能性あり。実機の元写真は、より高解像度の想定
- 背景はすべて黒幕。ヘアバンド（ロゴ入り）・黒いケープ着用で統一されている

## 2. 気づいた点と設計への反映

| # | 気づいた点 | 設計への反映 |
|---|---|---|
| 1 | セットごとに写真の並び順がバラバラ | 枠ごと（正面/斜め/あおり/横顔）に写真を選ぶ方式にし、選ぶ順番に依存しない |
| 2 | 左向きのセット（C）がある | 向きは問わずそのまま使う（反転しない）。左向きでも顔検出・配置が効くことを検証する |
| 3 | 人によって撮影距離が違い、顔の大きさがかなり違う（A の正面は大きめ、C は小さめ） | 顔の大きさをそろえる自動拡大縮小が効果大 |
| 4 | **あおり**は顔が画面の下寄りで、首が長く写る。頭頂部はヘアバンドで隠れる | あおりは「顔検出の枠」ではなく、「頭頂部〜顎下」の範囲を基準に配置する専用ルールが必要 |
| 5 | **横顔**は顔検出の精度が落ちやすい。目は片目のみ | 横顔は人物の輪郭（髪・頭の形）も使って配置する。目元ぼかしは自動＋手動補正 |
| 6 | 横顔 B の右側に**黒幕の端（カーテンの境目）**が写っている | 拡大で枠外にできるだけ追い出す。完全に消すのは対象外（必要なら手動で寄せる） |
| 7 | あおりの目は細く、上を向いている（白目が多い） | 目の検出が外れやすい想定。手動でぼかし位置を動かせるようにする |
| 8 | 斜めは顔が画面の中央からずれている（後頭部側に余白） | 「顔の中心」をセルの中央に置く。写真の中心ではない |
| 9 | 元写真は 3:2。セル（16:9）より縦が長い | 上下を少し切ることになるが、頭頂部〜首元は十分入る |

## 3. 技術検証で確かめること（試作フェーズ）
- MediaPipe の顔検出が、正面・斜め・あおり・横顔それぞれで検出できるか（12枚で成功率を確認）
- 目の位置の検出精度（特にあおり・横顔）
- iPhone の Safari で高解像度写真4枚を処理したときの速度とメモリ
