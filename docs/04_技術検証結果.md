# 技術検証結果（テスト写真12枚）

実施日: 2026-11-11
検証コード: `tools/validation/`（detect.py = 検出、compose.py = 自動配置＋ぼかしの試作）
使用技術: MediaPipe（Web アプリでも同じモデルを使える）
出力: `tools/validation/out/collage_setA〜C.jpg`（3840×2160。写真を含むので Git 管理外）

## 1. 検出の成功率

| 検出 | 正面 (3) | 斜め (3) | あおり (3) | 横顔 (3) | 合計 |
|---|---|---|---|---|---|
| 顔の位置（顔検出） | 3 | 3 | 3 | 3 | **12/12** |
| 目の輪郭（顔ランドマーク） | 3 | 3 | 3 | 1（左向きのCのみ） | **10/12** |
| 目のおおよその位置（姿勢推定） | 3 | 3 | 3 | 3 | 12/12 |
| 人物の輪郭（頭頂部の推定） | 3 | 3 | 3 | 3 | 12/12 |

左向き（セットC）も問題なく検出できた → 向きを問わない運用で OK。

## 2. 自動配置
- 12/12 で、頭頂部〜顎先が枠内に収まり、顔の大きさもおおむねそろった
- 配置ルール（現在の値、設定で変更可）
  - 正面・斜め・横顔: 頭頂部〜顎先 = 枠の高さの 66%、頭頂部を上から 12% の位置
  - あおり: 首が長く写るため別ルール（44%、上から 22%）
- 写真が枠より小さい部分は、写真の背景色で埋める → 境目がうっすら見える場合あり（実機の元写真は高解像度なので、拡大で目立たなくなる見込み）

## 3. 目元ぼかし
| 角度 | 結果 |
|---|---|
| 正面・斜め・あおり | 9/9 で両目を正確にぼかせた |
| 横顔（左向きC） | 正確 |
| 横顔（右向きA・B） | 目の輪郭が取れず、予備手段（姿勢推定）でおおよその位置をぼかした。**少しずれる**（B は鼻側に寄った） |

→ 想定どおり、**横顔のぼかしは手動で微調整が必要になる場合がある**。該当枠に「要確認」マークを出す設計で対応。

## 3.5 背景を真っ黒に（2026-11-11 追加）
- 要望: 境目をなくすため背景は真っ黒。顔の明るさは変えない。白飛びを出さない
- 処理:
  1. シャドウだけを締めるトーンカーブ。写真ごとの黒幕の明るさ以下は 0、明るさ 64 以上（肌・顔）は一切変えない
  2. 人物領域から十分離れた背景はマスクで完全に 0（黒幕の端・しわも消える）
  3. 写真が枠に足りない部分も真っ黒で埋める → 境目がなくなった
- 確認結果（12枚）:
  - 背景の明るさ: 処理後すべて 0（真っ黒）
  - 白飛び（250以上の画素）: 処理前後で増加なし
  - 肌の画素: ほぼ不変（輪郭のごく一部のみ、背景とのなじませで変化）
- 注意: 黒髪・黒い服は背景になじむ（元から暗い部分なので見た目の変化は小さい）

## 3.6 顔の大きさ（2026-11-11 変更）
- 正面・斜め・横顔: 頭頂部〜顎先 = 枠の高さの 76%（旧 66%）、頭頂部を上から 7%
- あおり: 52%（旧 44%）、上から 16%

## 4. 結論
- 写真を選ぶだけで、12枚中 10枚は手直し不要の見込み
- 手直しが必要になりやすいのは「横顔の目元ぼかし」のみ
- MediaPipe で要件を満たせるので、Web アプリ方式で進めて問題ない

## 5. 残る確認（実機で）
- iPhone の Safari での処理速度（4枚で数秒以内が目標）
- 高解像度の元写真（HEIC）での動作・メモリ
- ぼかしの強さ・範囲、顔の大きさの好み（試作画像を見て調整）
